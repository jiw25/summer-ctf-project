# 🛠️ [CTF 문제 개발] 주간 스프린트 정리 (8월 3주차)

> **🎯 문제 핵심 기획 의도**
> 1단계: Command Injection ➔ 관리자 패스워드 획득
> 2단계: 사서 포털 관리자 로그인
> 3단계: 도서 상세 페이지 Stored SSTI ➔ Flag 획득

## ✅ 이번 주 완료한 작업 (Done)

### 1. 🚨 커맨드 인젝션 Unintended(언인텐) 취약점 패치

* **이슈:** `127.0.0.1 && cat flag.txt` 페이로드 입력 시, 기획된 로그인 및 SSTI 단계를 거치지 않고 바로 플래그를 획득하는 치명적인 언인텐(Unintended) 발견.
* **해결 및 조치 사항:**
* `app.py` 내부의 검증 방화벽인 `BLACKLIST` 변수에 플래그 관련 키워드 추가 차단.
* 🔒 **수정 전:** `['>', '<', '|', '*', '?', ';', 'rm', 'echo', 'app.py']`
* 🔒 **수정 후:** `['>', '<', '|', '*', '?', ';', 'rm', 'echo', 'app.py', 'flag']`
* 결과적으로 참가자는 무조건 `admin_password.txt`를 읽고 정석 루트를 타도록 유도 완료.



### 2. 🛡️ 타 공격 벡터를 통한 언인텐 가능성 점검 (보안 감사)

* **SQL Injection (SQLi):** 데이터베이스를 사용하지 않고 파이썬 메모리 리스트(`BOOKS`)로 데이터를 관리하므로 구조적으로 발생 불가 (안전).
* **XSS / CSS Injection:** `/login` 실패 시 사용자 입력값이 화면에 그대로 렌더링(Reflection)되지 않도록 구현되어 있어 공격 불가 (안전). `index.html` 또한 `escape()` 처리되어 방어됨.
* **Session Forging (세션 위조):** `os.urandom(24)`를 사용하여 매번 시크릿 키가 랜덤하게 생성되므로 세션 조작 원천 차단 (안전).
* **결론:** 기획된 취약점(Command Injection, SSTI) 외의 허무한 언인텐 루트는 모두 안전하게 방어됨을 검증 스크립트로 확인 완료.

### 3. 🎨 상세 페이지 CSS 및 로직 수정 (Stored SSTI로 고도화)

* **이슈:** 기존에는 정보 수정 시 임시 페이지에서만 결과가 뜨고 실제 데이터가 바뀌지 않아 몰입도가 떨어짐.
* **해결 및 조치 사항 (Stored SSTI 구현):**
* **Backend (`app.py`):** 관리자가 수정한 내용을 실제 `BOOKS` 리스트에 저장하고 리다이렉트 하도록 로직 수정. 템플릿 렌더링 시 발생한 에러 메시지를 노출하도록 하여 훌륭한 해킹 힌트로 작용하게 만듦.
* **Frontend (`detail.html`):** 화면 전환 없이 깔끔하게 편집할 수 있도록 JS 기반의 **토글형 편집 버튼(편집 모드 켜기/끄기)** 추가.
* CSS 스타일링을 통해 관리자 전용 인터페이스 느낌(붉은색 경고 박스 및 숨김 폼)을 강화하여 문제의 퀄리티 상승.
